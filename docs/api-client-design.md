# 接口请求工具功能设计

状态：设计草案，尚未实现。  
日期：2026-09-08

## 1. 功能目标

在 Eidolon 的 Tauri 应用中增加一个接口请求工具，用于按项目管理接口、编辑并发送 HTTP 请求、查看响应。

核心能力是 **AI 根据接口说明、字段约束或已有示例，生成可以编辑的请求体数据**。用户检查数据后，再决定保存或发送。

典型场景：用户在“订单系统”项目的“订单”分组中创建“新增订单”请求，填写地址与字段说明，让 AI 生成包含三件商品的订单数据，修改其中的用户 ID，向测试环境发送请求并查看结果。

这里的 Mock 指填充请求数据。首版不提供模拟响应的 Mock 服务端。

## 2. 当前项目基础

根据当前代码确认：

- 前端使用 Vue，已有应用布局、路由和设置页。
- Tauri 的 Rust 端通过 `LocalJsonStore` 将模型配置、Agent、会话等数据保存到本地 JSON 文件。
- 当前未接入 SQLite，Rust 依赖中没有 rusqlite 或 SeaORM。
- 已有模型供应商和默认模型配置，可以作为新功能接入 AI 的基础；仍需增加专用于请求体生成的调用流程。

本功能使用 SQLite 保存新增数据。现有 JSON 数据迁移不纳入本次范围。

## 3. 首版范围

| 能力 | 首版设计 |
| --- | --- |
| 项目管理 | 创建、重命名、删除项目 |
| 分组管理 | 项目内创建、重命名、删除分组，支持手动调整顺序 |
| 请求管理 | 创建、保存、复制、删除请求，移动到同项目其他分组 |
| HTTP 方法 | GET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS |
| 请求配置 | 地址、Query 参数、Headers、Body |
| Body 格式 | 无请求体、JSON、原始文本、URL 编码表单 |
| AI 数据生成 | 根据说明和示例生成 JSON 请求体，预览后应用 |
| 环境配置 | 项目级环境、基础地址和变量 |
| 请求执行 | 发送、取消、超时处理 |
| 响应查看 | 状态码、耗时、响应头、响应体，JSON 格式化与文本查看 |
| 历史记录 | 查看执行快照，将历史内容恢复到编辑器 |
| 本地持久化 | SQLite 保存，应用重启后可继续使用 |

首版分组采用一层结构：**项目 → 分组 → 请求**。创建项目时生成“默认分组”，新请求必须属于一个分组。数据结构预留父分组字段，但首版不开放多层分组交互。

暂缓：文件上传和 multipart、WebSocket、SSE 流式查看、GraphQL 专用编辑器、OAuth 登录流程、前后置脚本、批量执行、自动断言、团队同步、OpenAPI/cURL 导入导出，以及 AI 自动连续调用接口。

## 4. 页面与操作流程

在应用导航增加“接口请求”入口，作为独立功能页面。

### 4.1 工作区

| 区域 | 内容 |
| --- | --- |
| 左侧 | 项目切换、分组和请求列表、按名称搜索、新建入口 |
| 主区顶部 | 请求名称、环境选择、HTTP 方法、URL、保存和发送按钮 |
| 主区中部 | Params、Headers、Body 编辑区域；Body 中提供“AI 生成”入口 |
| 主区底部 | 响应结果与历史记录 |
| AI 面板 | 生成说明、参考内容、模型选择、生成结果、应用操作 |

首版一次编辑一个请求。切换请求、项目或关闭页面时，如果有未保存修改，提供保存、放弃、继续编辑选项；不静默丢失内容。

### 4.2 创建与发送

1. 创建项目，设置测试环境的基础地址。
2. 在分组下新建请求，填写名称、方法和地址。
3. 配置 Query、Headers 和 Body；可手动填写，也可使用 AI 生成 JSON。
4. 检查请求，点击“发送”。允许发送未保存的编辑内容，发送本身不覆盖已保存请求。
5. 展示响应，并记录本次实际执行的请求快照。
6. 用户点击“保存”后，更新请求定义。

空项目、空分组均提供明确的新建入口。删除项目或分组时说明将一并删除的请求与历史记录，并要求确认。

## 5. AI 生成请求体

### 5.1 输入

用户不必先建立完整字段模型。首版提供两个输入区：

- **生成要求**：例如“生成一个订单，包含三件商品，金额保留两位小数，收货地址使用中文”。
- **参考内容**：粘贴字段说明、接口文档片段或 JSON 示例；可选择带入当前 Body。

请求名称、方法、未展开变量的 URL 路径可以作为辅助上下文。默认不带入 Headers、环境变量值和响应历史，也不读取项目文件。

用户可以在生成前查看将提交给模型的参考内容。当前 Body 由用户主动勾选带入，避免无意提交已有真实业务数据。

沿用已有供应商和模型配置，提供独立的“请求体生成”默认模型设置。未配置可用模型时，引导到设置页，仍可手动编辑和发送请求。

### 5.2 输出与应用

1. 用户点击“生成”，AI 面板进入生成中状态，支持取消。
2. 结果作为候选内容展示，不立即修改 Body。
3. 对候选结果进行 JSON 语法校验。合法 JSON 可以是对象、数组或其他 JSON 值，不强制对象顶层。
4. 用户可编辑候选结果，或修改要求后重新生成。
5. 点击“应用到请求体”后，用候选内容整体替换当前 Body；提供撤销本次替换的操作。
6. 应用后请求变为未保存状态，仍需用户单独保存或发送。

若当前 Body 不是 JSON，应用前明确提示将切换为 JSON 格式。生成期间原 Body 可以继续编辑，应用时以用户明确点击为准，不自动合并。

首版不做按字段智能合并，也不宣称能完整校验业务规则。JSON 语法通过只表示格式有效；外键 ID 是否存在、金额是否符合接口规则，仍由用户或实际接口验证。

### 5.3 异常与状态

- 无效 JSON：保留结果并展示错误，允许编辑后重新校验，禁止直接应用。
- 模型超时、额度不足或网络失败：显示可理解的原因，保留生成要求与原 Body。
- 取消生成：停止等待，迟到的结果不得覆盖当前候选内容。
- 切换请求：生成任务绑定原请求，结果不得应用到另一个请求。
- 再次生成：保留已应用的 Body，新结果仍需手动应用。

保存生成要求和参考内容，便于下次复用；首版不建立完整 AI 对话，也不单独保存每次生成记录。应用并保存后的数据归请求定义所有，发送后的数据归执行历史所有。

## 6. 请求编辑与环境规则

### 6.1 参数与请求头

Query、Headers、URL 编码表单均使用可启用或禁用的键值行，支持重复键并保留顺序。不要用普通对象保存，以免丢失重复字段。

粘贴完整 URL 时，将查询参数解析到 Params 编辑区，URL 输入保留基础地址与路径；后续由 Params 统一管理查询参数，避免重复拼接。禁用的行不发送。

Headers 名称按大小写不敏感处理。根据 Body 类型补充默认 Content-Type；用户显式设置时优先使用用户值，存在明显冲突时提示。首版通过 Headers 配置 Bearer Token、API Key 等认证，不单独实现认证向导。

### 6.2 环境变量

每个项目拥有独立环境，例如开发环境、测试环境。每个环境包含 `base_url` 和其他变量，使用 `{{变量名}}` 引用。

- 绝对 URL 直接使用；相对路径通过所选环境的基础地址解析。
- 变量可用于 URL、Query、Headers 和 Body。
- 首版只有环境一级变量作用域，没有全局、项目、分组之间的多层覆盖。
- 存在未定义变量时阻止发送，并列出缺失变量。
- 请求定义保留变量表达式；发送时生成独立快照，之后切换环境不改变已有历史。
- JSON 模式先替换变量再做语法校验。首版采用文本替换，不自动推断或转换类型；字符串值需要正确的 JSON 引号与转义。

敏感变量在界面中遮罩。首版为本机工具，变量可能以明文落盘，遮罩不代表加密；历史记录对敏感变量值和常见认证头脱敏，不保存这些凭据的实际值。恢复此类历史时需要使用当前环境的凭据重新解析，并明确标记它不是完整的原始报文。

## 7. 请求执行与响应

请求由 Rust 端 HTTP 客户端执行。前端通过 Tauri command 提交请求快照，不直接通过 WebView 发起目标接口请求。

- 仅支持 HTTP/HTTPS，支持访问本机和内网服务。
- 默认超时建议 30 秒，可针对请求调整。
- 同一编辑器内一次只执行一个请求，执行中禁用重复发送。
- 每次执行具有独立 ID，取消和响应回传均按该 ID 关联。
- 首版不自动重试，不自动跟随重定向，不持久化 Cookie；3xx 响应直接展示。
- HTTPS 默认校验证书；自签名证书支持后续单独设计。
- 取消表示客户端停止等待，服务端可能已经执行，不显示为“已回滚”。

HTTP 4xx/5xx 属于收到的正常响应，应展示状态码和响应体；连接失败、超时属于执行错误，单独显示原因。

响应展示状态码、客户端总耗时、已接收的响应体大小、响应头、原始文本，合法 JSON 可格式化查看。二进制响应首版仅提示类型和大小，不强制转换为文本。

建议响应体接收上限为 5 MiB，超出后终止继续读取并显示“响应超过上限”；禁止无上限缓冲。历史最多保存 1 MiB 响应内容，超出时标记截断，JSON 被截断后按文本展示。具体阈值作为实现时可调整的产品默认值。

## 8. SQLite 数据设计

SQLite 数据库建议放在 Tauri 应用数据目录下，文件名为 `api-client.sqlite`。前端通过 Rust 服务读写，不直接操作数据库。

以下为逻辑设计，具体字段类型和迁移 SQL 在实现时确定。

| 表 | 主要内容 |
| --- | --- |
| `api_projects` | ID、名称、描述、排序、创建时间、更新时间 |
| `api_groups` | ID、项目 ID、父分组 ID（首版为空）、名称、排序、时间 |
| `api_requests` | ID、分组 ID、名称、方法、URL、Query/Headers JSON、Body 类型及内容、超时、AI 生成要求与参考内容、排序、时间 |
| `api_environments` | ID、项目 ID、名称、基础地址、变量 JSON、时间 |
| `api_request_histories` | ID、请求 ID、环境名称快照、脱敏请求快照、响应状态与响应头、受限响应体、截断标记、耗时、执行状态、错误、时间 |
| `schema_migrations` | 已执行的数据库迁移版本 |

请求通过分组归属项目，避免重复维护两套归属字段。环境选择时验证其与请求属于同一项目。为分组项目 ID、请求分组 ID、历史请求 ID 与执行时间建立索引。

灵活结构用 JSON 文本保存：Headers 和 Query 是带启用状态的数组；Body 按类型保存文本或表单数组。用于查询、排序、关联的字段独立存放。

数据库必须启用外键约束。删除项目、分组或请求及其关联历史时使用事务，避免残留。迁移以递增版本执行，不改写已经应用的迁移。

首版每个请求默认保留最近 100 次执行记录，提供清空历史操作。历史写入失败时仍展示已经收到的响应，并明确提示未保存历史，不能让用户误以为请求没有执行而再次发送。

SQLite 驱动或 ORM 的选型留到实现阶段，不要求为了这个功能迁移现有存储层。

## 9. 职责划分

- **Vue 页面**：请求编辑、候选数据预览、校验提示、响应展示、未保存状态管理。
- **Rust 请求服务**：校验协议与环境、构建实际请求、发送与取消、限制响应大小。
- **Rust AI 生成服务**：读取现有模型配置、组装明确的生成上下文、返回候选结果，不持有发送业务接口的权限。
- **Rust 数据仓库**：项目、分组、请求、环境、历史记录的 SQLite 读写与事务。

请求定义、编辑中的草稿、AI 候选结果、执行快照是四种不同状态。保存只更新请求定义；应用 AI 结果只更新草稿；发送冻结当时的草稿和环境。迟到的生成或执行结果不能覆盖后续编辑。

## 10. 实现顺序与验收

按三个阶段实现，但完整首版必须包含 AI 生成。

### 阶段一：本地请求闭环

接入 SQLite，完成项目、分组、请求管理，支持配置请求和查看响应。

验收：创建一个 POST JSON 请求，保存后重启仍存在；可以修改后发送，看到响应状态、响应头和响应体；发送未保存内容不覆盖请求定义。

### 阶段二：AI 生成请求体

接入已有模型配置，完成生成要求、参考输入、候选校验、应用和撤销。

验收：根据字段说明生成 JSON，应用前原 Body 不变；无效 JSON 不能应用；应用后可以修改再发送；生成失败或取消不丢失原内容。

### 阶段三：环境与执行历史

完成变量解析、历史快照、取消与超时、响应上限、数据清理。

验收：切换测试环境后发送到对应地址；缺失变量阻止发送；历史不随请求定义变化；脱敏与截断有明确标记；从历史恢复只更新编辑器，不自动发送；超时或取消后可以再次操作。

实现前仍需验证已有模型调用代码的可复用范围，以及所选 HTTP 客户端的取消和响应大小控制方式。本文件描述目标行为，不代表上述能力已接入。
